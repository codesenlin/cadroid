# 启动入口与页面层级行为规范

> 状态：分析定稿，待实现  
> 范围：cadroid 壳层 + CA 脚本 UI 的启动、权限、悬浮与退出行为  
> 日期：2026-11-28  
> 说明：本文只记录现象、预期和实现约束，暂不包含代码改动。

## 1. 背景

当前启动相关的问题不是单个按钮失效，而是三层页面和两套形态没有统一的生命周期：

```text
LandingActivity   权限检查页
SplashActivity    初始化页
Main UI           主界面
```

两套形态：

```text
页面模式：没有系统悬浮窗权限，全部在命令助手自己的界面内
悬浮模式：有系统悬浮窗权限，球和主界面可以盖在其他应用上
```

核心矛盾：

```text
权限页该保留的时候被提前关闭
初始化页该结束的时候被留在后台
主界面该收回球的时候没有球
缺少显式的退出入口
桌面图标入口没有稳定收敛到权限页
```

## 2. 最终行为规范

### 2.1 入口与返回

| 操作 | 最终行为 |
|---|---|
| 桌面图标 | 永远进入权限检查页 |
| 权限页返回 | 退回桌面，但保留服务；有悬浮窗权限时球保留 |
| 悬浮球 | 直接开 / 收主界面 |
| 主界面返回 | 收拢回悬浮球，不回权限页、不回桌面 |
| 权限页与主界面 | 可以同时存在、互不干扰；确认场景是有悬浮窗权限且主界面不是覆盖全屏 |
| 全屏 / 悬浮窗切换 | 两者都是悬浮窗，只是尺寸不同；返回都收回到球 |
| CA 菜单「退出命令助手」 | 结束服务 + 关闭权限页/球/主界面 + 清除任务，不二次确认 |
| 返回 | 只收起当前层，不等于退出 |
| 冷启动结束 | 回桌面后，图标下一次点击必须是权限页；初始化任务不能截胡 |

### 2.2 两种模式

| 模式 | 球 | 主界面 | 跨应用使用 |
|---|---|---|---|
| 页面模式，无系统悬浮窗权限 | 页面内球 | 页面内主界面 | 复制后切后台，去游戏里手动粘贴；不需要应用悬浮窗 |
| 悬浮模式，有系统悬浮窗权限 | 系统悬浮球 | 悬浮窗主界面，可全屏/小窗 | 球直接盖在游戏上，复制后可点球回来 |

页面模式的“跨应用粘贴”定义为：

```text
进入命令助手 → 复制命令 → 切到后台 → 进入游戏 → 手动粘贴
```

不要求在游戏上方显示球，也不要求无障碍悬浮层。

### 2.3 权限与冷启动

```text
未授权：
  权限页 → 返回桌面 → 服务保留

授权瞬间：
  不要求手动重启
  自动切换到悬浮模式并创建球
  权限页可以保留在后台

冷启动：
  初始化完成 → 销毁初始化任务
  悬浮模式：回桌面/原应用，只保留悬浮球
  页面模式：留在权限页，不自动返回桌面
  回到桌面后，图标下一次点击必须进权限页
```

初始化页也可以选择“保留但让路”或“销毁后重建”，但最终状态必须是：

```text
冷启动完成并回到桌面后
桌面图标下一次点击 → 权限检查页
```

## 3. 问题清单

| 编号 | 场景 | 实际表现 | 预期表现 | 性质 |
|---|---|---|---|---|
| 1 | 无悬浮窗权限，页面模式 | 每次停在权限检查页；没有球，也进不了主界面 | 页面模式有页面内球，能进主界面；复制后可切后台粘贴 | 页面模式没有真正实现 |
| 2 | 应用未关闭时授予悬浮窗权限 | 授权瞬间权限页就消失；之后桌面图标直接进主界面；没有球 | 权限页保留；图标仍进权限页；授权后自动切悬浮模式并出现球，不用重启 | 权限页生命周期 + 入口路由错误 |
| 3 | 第 2 条后续，主界面已打开 | `CA` 菜单无退出；没有球，返回直接到桌面；只能通知栏退出或系统强停 | 返回收回到球；`CA` 菜单提供「退出命令助手」；退出结束服务与所有层 | 缺少回退层 + 缺少退出路径 |
| 4 | 冷启动前已授予悬浮窗权限 | 点球收起主界面回桌面，球保留；球能正常再开主界面；但再点桌面图标无反应 | 桌面图标应进入权限页 | 桌面图标入口失效 |
| 5 | 冷启动完成自动回桌面 | 初始化页像按了一次返回一样退到桌面；最近任务仍保留「初始化模块」卡片；第一次和后续点击落点不一致 | 回桌面后图标必须进权限页；初始化页可保留/销毁/重建，但不能截胡 | 初始化任务残留 + 入口未收敛 |

### 3.1 关键补充观察

- 未授权时，权限页返回后台后仍然存在。
- 授予悬浮窗权限的那一刻，还没点进主界面，权限页就已经消失。
- 冷启动结束不是初始化页“一闪”，而是它执行了一次类似返回的退后台动作。
- 最近任务中可以看到「命令助手 / 初始化模块」卡片。
- 参考分支 `com.huangyx.ca` 0.3.0 在 `SYSTEM_ALERT_WINDOW: deny` 下仍有球，说明页面模式本可以不依赖系统悬浮窗。

## 4. 根因分析

### 4.1 权限页被提前结束

现象链：

```text
未授权：权限页在后台还在
授予权限的瞬间：还没点主界面，权限页就消失了
之后：桌面图标变成主界面入口
主界面关闭：没有权限页可回
```

权限状态变化触发了权限页提前结束。具体触发点还需要在代码里确认，但现象已经明确。

### 4.2 初始化页没有真正结束

当前路径是：

```text
初始化完成 → moveTaskToBack
```

不是 `finish` / `removeTask`，所以最近任务里留下：

```text
命令助手 / 初始化模块
```

旧任务可能先于权限页被命中，导致第一次和后续点击落点不一致。

### 4.3 页面模式缺失

无权限时直接退化成权限检查页：

```text
没有页面内球
没有页面模式主界面
```

页面模式需要自己具备一套不依赖 `SYSTEM_ALERT_WINDOW` 的球和主界面，而不是把“没有权限”直接当成“不能使用”。

### 4.4 退出路径缺失

```text
CA 菜单没有退出
返回只收起当前层
后台没有主界面任务
权限页也已被关闭
```

只剩通知栏退出或系统「正在运行的服务」强停，不是正常关闭路径。

## 5. 系统自由窗口

系统小窗只是系统承载 Activity 的一种方式，不作为本次专项需求，也不作为验收条件。

它证明了：

```text
权限页本身把用户挡在外面
换成系统小窗，也还是这个打不开的界面
```

因此重点不是适配小窗，而是让页面模式本身可用。

## 6. 验收清单

```text
[ ] 无权限时，页面模式有页面内球
[ ] 无权限时，页面球能开/收主界面
[ ] 无权限时，复制后切后台，剪贴板可用
[ ] 有权限时，授权后自动出现球，不用重启
[ ] 桌面图标始终进权限页
[ ] 主界面返回收回到球
[ ] 权限页返回桌面，服务保留
[ ] 主界面打开时还能打开权限页，互不干扰（有权限且非覆盖全屏）
[ ] CA 菜单有「退出命令助手」
[ ] 退出后服务、球、主界面、任务全部清除
[ ] 冷启动后图标第一次点击就是权限页
[ ] 页面模式冷启动后留在权限页，不自动回桌面
[ ] 悬浮模式冷启动后回桌面/原应用并保留球
[ ] 初始化任务不截胡桌面图标
[ ] 全屏/悬浮窗切换后，返回都回球
[ ] 系统小窗不作为专项需求
```

```text
系统自由窗口
→ 系统行为，不作为专项适配要求
```

## 8. 后续实现顺序

```text
1. 固定入口语义：图标 → 权限页；球 → 主界面
2. 修权限页生命周期：授权后不自动结束，作为根页面保留
3. 修初始化页生命周期：回桌面前 finish/remove，或保证不截获入口
4. 修主界面返回：收拢回球，而不是直接回桌面
5. 补 CA 菜单「退出命令助手」
6. 实现页面模式：页面内球 + 页面模式主界面
7. 最后清理两个进程条目等观察项
```
